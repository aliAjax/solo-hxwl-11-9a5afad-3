# hxwl-11 眼科验光记录 · 验光处方复核台

复查医生对照同一患者不同日期的双眼屈光数据，标记/关闭处方冲突，并把复核事项流转为
**待修正 / 需升级 / 已确认**。

## 技术栈

React 19 + Vite + TypeScript + CSS（无后端，Mock 服务端 + localStorage 持久化）

## 本地运行

```bash
npm install
npm run dev      # http://localhost:5111
```

## 业务规则

| 角色 | 权限 |
| --- | --- |
| 验光师 | 只能**标记冲突**（对照多日期双眼屈光数据） |
| 复查医生 | **关闭冲突**、流转**待修正/需升级**、**确认处方**（确认权仅医生） |
| 门店顾问 | 只读 |

- **冲突未关闭不能确认**：存在 open 冲突时确认按钮锁定。
- **冲突内容级幂等**：同一事项上同指标 + 同说明（忽略首尾/重复空白）的冲突，无论间隔多久、
  刷新、断网重放还是多标签并发，只保留一条未关闭冲突与一条标记审计；不同指标/说明仍可登记；
  已关闭的同内容冲突必须由验光师**显式重新开启**（不能静默新建）。
- **跨标签并发保存**：所有提交在服务端存储锁保护下，按**同一条最新状态顺序落库**
  （锁内重读 → 应用 → 写回，rev 单调自增）。localStorage 无原子 CAS，锁采用
  "写后等待确认、最后写入者唯一获胜"，杜绝两个标签同时进临界区；锁等待超时（`LOCK_BUSY`）
  或网络中断时动作**先持久化进本标签 outbox** 并退避自动重试，不丢失也不阻塞后续提交；
  持锁标签崩溃遗留的陈旧锁在 TTL 后可被接管。客户端按**标签分键**存储 outbox（含心跳），
  失活/关闭标签遗留的队列由存活标签自动接管补传；storage 事件驱动双方视图以服务端快照为
  基底 rebase，即时汇聚，处理人与时间均为真实提交者。
- **每次决定留痕**：处理人、角色、时间（离线时为实际操作时刻）、动作与备注写入处理记录；
  审计 id 由 actionId 派生，跨标签也不会碰撞。
- **重复提交只生效一次**：客户端短窗口去重 + actionId 服务端幂等（outbox 重放、跨标签接管安全）。
- **刷新/断网恢复**：本标签数据（含 outbox、待同步标记）独立分键持久化，同标签刷新复用 clientId
  即时恢复；断网期间操作照常生效并排队，恢复后按序重放，以服务端快照对账。
- **旧数据迁移**：v1 服务端状态、无版本客户端快照及早期共用快照键均可直接读取并升级到 v2
  （补 rev、归一键值、outbox 分键），升级后可继续操作。
- 顶部可切换身份、模拟断网/恢复、重置演示数据。

## 验证

```bash
npm run verify   # Node 断言 130 项
npm run build    # tsc 类型检查 + vite 构建
```

Node 断言覆盖：角色权限、越级/终态门禁、冲突未关闭禁止确认；同 actionId 与同内容冲突幂等
（跨刷新/断网重放/跨标签/空白归一）、显式重新开启；两标签 12 轮与 20 条突发并发不同决定零
丢失零重复、处理人/时间真实、rev 严格等于提交数；180ms 延迟下 16 条快速并发；陈旧锁 TTL
接管、锁等待超时入队重试、关闭标签遗留 outbox 被新标签接管；断网→刷新→恢复；v1 旧数据迁移。

`scripts/e2e.mjs` 为真实浏览器 E2E（需本机 Playwright + Chromium，61 项）：按钮级权限、
越级禁用、双击去重、断网→刷新→恢复、两真实标签 5 轮并发后刷新一致、陈旧锁恢复、
关闭标签接管、显式重开、旧数据迁移。
