# hxwl-11 眼科验光记录 · 验光处方复核台

复查医生对照同一患者不同日期的双眼屈光数据，标记/关闭处方冲突，并把复核事项流转为
**待修正 / 需升级 / 已确认**。

## 技术栈

React 19 + Vite + TypeScript + CSS（无后端，Mock 服务端 + localStorage 持久化）

## 本地运行

```bash
npm install
npm run dev      # http://localhost:5111
```

## 业务规则

| 角色 | 权限 |
| --- | --- |
| 验光师 | 只能**标记冲突**（对照多日期双眼屈光数据） |
| 复查医生 | **关闭冲突**、流转**待修正/需升级**、**确认处方**（确认权仅医生） |
| 门店顾问 | 只读 |

- **冲突未关闭不能确认**：存在 open 冲突时确认按钮锁定。
- **冲突内容级幂等**：同一事项上同指标 + 同说明（忽略首尾/重复空白）的冲突，无论间隔多久、
  刷新、断网重放还是多标签并发，只保留一条未关闭冲突与一条标记审计；不同指标/说明仍可登记；
  已关闭的同内容冲突必须由验光师**显式重新开启**（不能静默新建）。
- **跨标签并发保存**：服务端在共享存储上以互斥锁执行"读最新 → 应用 → 写回（rev 自增）"，
  两个标签同时提交的不同决定都会落库；客户端监听 storage 事件，以服务端快照为基底 rebase
  本地 outbox，双方视图即时汇聚，处理人与时间均为真实提交者。
- **每次决定留痕**：处理人、角色、时间（离线时为实际操作时刻）、动作与备注写入处理记录。
- **重复提交只生效一次**：客户端短窗口去重 + actionId 服务端幂等（断网 outbox 重放安全）。
- **刷新/断网恢复**：客户端快照（含 outbox 与待同步标记）持久化；断网期间操作照常生效并排队，
  恢复网络后按序重放，以服务端快照对账。
- **旧数据迁移**：v1 服务端状态与无版本客户端快照可直接读取并升级到 v2（补 rev、归一键值）。
- 顶部可切换身份、模拟断网/恢复、重置演示数据。

## 验证

```bash
npm run verify   # Node 断言 97 项：权限/越级/门禁/内容幂等/重开/断网重放/跨标签并发/v1迁移
npm run build    # tsc 类型检查 + vite 构建
```

`scripts/e2e.mjs` 为真实浏览器 E2E（需本机 Playwright + Chromium，48 项：按钮级权限、
越级禁用、双击去重、断网→刷新→恢复、双标签并发不同/相同决定、显式重开、旧数据迁移）。
